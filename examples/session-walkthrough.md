# 一场典型访谈长什么样

> **说明**：下面是按本技能规则整理的**示意流程**，用于说明交互节奏与产出形态，不是某次真实会话的逐字记录。
> 具体措辞会随宿主和模型变化。

## 场景

用户只有一句模糊想法，项目目录是空的。

---

### 第 0 步：Agent 先只读调查

按 §2，先读 `AGENTS.md`、`README`、目录结构、配置。空项目就如实说空项目——**不假装有代码**。
同时建立决策记录（初始都是"待决定"）。

### 第 1 轮：复述理解 + 问最关键的那个缺口

> 我先复述一下我的理解：你提到"想做个记账工具"，目前没有现成项目代码。
> 记账工具这个范围很大——可能是纯个人流水记录，也可能涉及多人分摊、对接银行账单。
> 我先问最影响后面所有问题的一个点。

**弹窗（WorkBuddy 版走 `AskUserQuestion`）：**

| 项 | 内容 |
| --- | --- |
| header | 主要场景 |
| question | 这个记账工具主要解决谁的什么问题？ |
| options[0] | **个人日常记账（推荐）**——只记录自己的收支，重点是记得快、看得清 |
| options[1] | 多人分摊——合租、旅行等场景下几个人算账 |
| options[2] | 经营流水——小店或副业，要出统计和报表 |

> 这里刻意**没有**一次性问"要什么数据库、要不要登录、要不要图表"。
> 按 §3，先问会改变后续问题的那个；上游没定，下游展开就是浪费。

### 第 2 轮：顺着答案往下

用户选了"个人日常记账"。Agent 复述新增确认项，只问下一步真正影响范围的：

| header | question | options |
| --- | --- | --- |
| 使用方式 | 你打算主要在什么设备上记？ | **手机上随手记（推荐）** / 电脑上整理 / 两者都要 |
| 记账频率 | 一天大概记几笔？ | 1—3 笔 / 5—10 笔 / 想起来才记 |

### 遇到含糊回答

用户对"数据要不要能导出"回答"随便，你看着办"。

按 §5：**「随便」不是授权。** Agent 应当把它标为「待决定」，说明"导出功能会让第一版范围明显变大，
且涉及数据归属问题，建议列为暂不做"，而不是自己拍板加进去，更不能顺手决定"数据公开"。

### 第 3 轮：逼具体

用户说"要安全、要好用"。按 §4，这类模糊词不能原样写进需求，要追问**可观察的行为**：

> "安全"我理解成两件具体的事，你确认一下是哪一种：
> ① 手机上别人拿到你手机也看不到账目（本地加密）；
> ② 数据只存在本机，不上传任何服务器。

### 展示初稿图（§6）

掌握目标和核心流程后，展示**两张初稿**并标明"草稿"：

- **需求思维导图**——以"个人记账工具"为中心，分层展开目标 / 用户 / 核心流程 / 功能范围 / 约束，
  区分必做与暂不做；
- **功能架构图**——用户 → 记录模块 / 统计模块 → 本地存储，有方向的连线表示"新增一笔 → 落库 → 汇总刷新"。
  未知项直接标"待确认"，AI 建议标"AI 建议"，**不提前写 PostgreSQL、不写框架名**。

对话优先渲染 Mermaid（导图用 `mindmap`，架构图用 `flowchart`），同时按 §6 保存两份独立 SVG 到
`docs/requirements/`：

```text
docs/requirements/个人记账工具-需求思维导图.svg
docs/requirements/个人记账工具-功能架构图.svg
```

保存后读回文件确认存在、内容完整，并逐图核对展示版与文件版一致。**存不上就如实说"SVG 未保存"**，
不冒称已存活。

### 收口：按 §7 的 7 条逐项检查

目标用户够清楚？核心流程含失败处理？必做与暂不做分开了？有没有阻塞缺口？
每条必做需求有没有可观察的验收标准？建议／待验证列清楚了吗？两张图和当前需求对得上吗？

全过之后，**复述一次实际使用过程**（优先用用户自己给的例子），只让用户纠正偏差。

### 最终交付：需求简报（§8）

```markdown
# 需求简报：个人记账工具
状态：待确认

## 目标、用户与使用环境
个人用户在手机浏览器上快速记录日常收支，重点解决"记一笔太麻烦导致坚持不下去"。
成功意味着：记一笔不超过 3 次操作，当天账目当天记完。

## 第一版范围
必做：R1 快速记账、R2 按周/月查看支出汇总
暂不做：多人分摊、银行账单导入、数据导出、云端同步

## 核心流程与规则
新增一笔 → 选收/支 → 填金额（必填，正数）→ 选分类 → 保存 → 列表顶部出现该笔
异常：金额为空或非数字时不保存并提示；重复提交同一笔时提示"可能已记录"。

## 需求思维导图
（展示最新图）+ SVG 文件入口

## 功能架构图
（展示最新图，标注"待确认"与"AI 建议"）+ SVG 文件入口

## 需求与验收
R1：用户能在 3 次操作内完成一笔记录。
AC1（R1）：在手机浏览器打开首页点"记一笔"，输入 25 元、选"餐饮"、保存，
         列表顶部立即出现该笔，且当日合计增加 25。
AC2（R1）：金额留空或输入"abc"时点击保存，应提示金额无效且不新增记录，不得保存 0 元记录。

## 数据、权限、界面与约束
仅本人使用，无多用户概念；数据存放位置：待决定（影响是否可跨设备）。

## 决策、假设与待验证项
用户已确认：使用场景为个人日常记账；主要在手机使用；第一版不做导出。
AI 建议／授权默认项：分类采用预设固定列表（低风险、可逆，用户未反对）。
待决定／待验证：本地存储还是服务器存储（阻塞，决定"换设备能否看到账目"）。
```

然后**集中确认一次**：

> 这是整理后的第一版需求。请指出需要修改的地方；确认后再进入开发计划，不开始写代码。

配一个弹窗，选项为「需求准确，可进入计划（推荐）」和「需要修改」，具体修改点走界面自带的自由输入框。

### 结束（§9）

用户确认后，标记「可进入计划」，交接需求编号、验收标准、已授权的默认项、非阻塞的待验证项和禁止事项，
以及两张最新图和 SVG 文件入口。

**到此为止。** 不拆任务、不写代码、不宣称已切换到计划模式——只提示"需求已可用于计划，你可以切到计划模式了"。
